# Проект: Прогнозирование стоимости недвижимости

## Общая постановка задачи

Построить и протестировать несколько моделей регрессии для прогнозирования цен объекта недвижимости на основе его характеристик, а также разработать приложение с формой входных данных, дашбордом и справочной информацией.

## Этап 1. Исследование данных (EDA)

### 1.1. Знакомство с данными

- Загрузить набор данных, вывести размерность (число строк и столбцов), определить типы данных по столбцам.
- Вывести первые и последние строки, выбрать случайную строку.
- Описать источник данных, единицы измерения и определить целевую переменную — цену.

### 1.2. Описательная статистика

- Рассчитать для числовых признаков минимум, максимум, среднее, медиану, стандартное отклонение и квартили.
- Для категориальных признаков определить частоты категорий и количество уникальных значений.
- Исследовать распределение цены: построить гистограмму и рассчитать коэффициент асимметрии.

### 1.3. Визуальный анализ

- Построить гистограммы ключевых числовых признаков: площади, количества комнат, года постройки и т. д.
- Построить диаграммы рассеяния «признак — цена» для основных признаков.
- Построить boxplot для числовых признаков и выявить выбросы.
- Построить тепловую карту корреляций между числовыми признаками.
- Проанализировать категориальные признаки относительно цены: например, столбчатые диаграммы средних цен по районам и типам домов.

### 1.4. Анализ пропусков и аномалий

- Подготовить таблицу или визуализацию количества и доли пропущенных значений по каждому столбцу.
- Проверить наличие дубликатов записей.
- Проверить логическую согласованность данных: отрицательная площадь, нереалистичный год постройки и другие аномалии.

### 1.5. Промежуточные выводы

- Сформулировать 3–5 гипотез о признаках, которые сильнее всего влияют на цену, и подтвердить их графиками и корреляциями.

## Этап 2. Предварительная обработка данных

### 2.1. Работа с пропусками

Для каждого типа пропусков выбрать и обосновать стратегию: удаление строк или столбцов, заполнение медианой или модой, заполнение на основе группировки (например, медианой по району), использование алгоритмов импутации (KNNImputer и т. п.).

### 2.2. Обработка выбросов

Выбрать методы обработки выбросов: удаление, винсоризация (ограничение по перцентилям), логарифмирование сильно скошенных признаков.

### 2.3. Кодирование категориальных признаков

- Использовать One-Hot Encoding для номинальных признаков.
- Использовать порядковое или меточное кодирование для порядковых признаков.
- При большом количестве категорий применить target/mean encoding или объединить редкие категории в «прочее».

### 2.4. Feature Engineering

- Создать новые признаки, например: «возраст здания» = текущий год − год постройки, «цена за м²», «расстояние до центра».
- Удалить неинформативные и сильно коррелированные признаки, проверить мультиколлинеарность с помощью VIF.
- При необходимости выполнить уменьшение размерности.

### 2.5. Масштабирование признаков

Обосновать применение StandardScaler, MinMaxScaler или RobustScaler в зависимости от выбранных моделей. Для линейных моделей масштабирование желательно, для деревьев решений обычно не требуется.

### 2.6. Разбиение данных

- Разделить данные на train/validation/test, например 70/15/15 или train/test 80/20 с кросс-валидацией.
- Зафиксировать random_state для воспроизводимости.
- Проверить отсутствие утечки данных: все преобразователи (скалер, кодер и т. п.) обучаются только на train.

## Этап 3. Построение модели регрессии

### 3.1. Требование: не менее 3 разных моделей

Рекомендуемый набор моделей (необходимо выбрать минимум три, желательно разной природы):

1. Линейная модель: Linear Regression, Ridge, Lasso или ElasticNet.
2. Модель на основе одиночного дерева: Decision Tree Regressor.
3. Бэггинг: Random Forest Regressor.
4. Бустинг: Gradient Boosting, XGBoost, LightGBM или CatBoost.
5. Опционально: KNN Regressor, SVR или нейронная сеть MLPRegressor.

### 3.2. Обучение и выбор гиперпараметров

- Для каждой модели подготовить базовую версию с параметрами по умолчанию.
- Выполнить подбор гиперпараметров с помощью GridSearchCV, RandomizedSearchCV или Optuna с кросс-валидацией на train.
- Зафиксировать лучшие параметры для каждой модели.

### 3.3. Метрики качества

Рассчитать для каждой модели на валидационной или тестовой выборке не менее 3–4 метрик:

- **MAE** — средняя абсолютная ошибка в единицах цены;
- **RMSE** — среднеквадратичная ошибка, чувствительная к большим ошибкам;
- **MAPE** — средняя абсолютная процентная ошибка;
- **R²** — коэффициент детерминации, доля объяснённой дисперсии.

Опционально можно рассчитать скорректированный R² и медианную абсолютную ошибку.

### 3.4. Сравнение моделей

- Свести все метрики в единую сравнительную таблицу.
- Построить график сравнения моделей по метрикам.
- Построить график «предсказание против факта» и график остатков для лучшей модели.
- Проанализировать важность признаков для деревьев и коэффициенты для линейных моделей.

### 3.5. Выбор финальной модели

- Обосновать выбор лучшей модели для приложения не только по метрикам, но и с учётом скорости вывода, интерпретируемости и устойчивости к переобучению.
- Сохранить модель и все препроцессоры (скалер, кодер) в формате pickle/joblib для использования в приложении.

## Этап 4. Приложение

### 4.1. Форма прогноза стоимости

- Создать интерфейс с полями для всех характеристик объекта: площадь, количество комнат, район, этаж, год постройки и т. д.
- Добавить проверку ввода: допустимые диапазоны и обязательные поля.
- По кнопке «Рассчитать» загрузить сохранённую модель и препроцессоры и вывести прогнозируемую цену.
- Желательно выводить доверительный интервал или диапазон прогноза, например ±MAE, а не только точечное значение.

### 4.2. Дашборд

Создать отдельную вкладку или ссылку на дашборд, отображающий:

- общую статистику датасета;
- распределения и средние цены по регионам и типам недвижимости;
- интерактивные графики для исследования данных;
- сравнение моделей и их метрики.

Дашборд может быть встроенным или реализованным в том же приложении на отдельной вкладке (например, многостраничное приложение Streamlit, Dash или отдельный лист веб-приложения).

### 4.3. Справка (Help)

Отдельная вкладка или раздел должен содержать:

- описание назначения приложения и инструкции по использованию;
- описание входных полей и единиц измерения;
- краткое описание используемой модели и её ограничений с учётом имеющихся данных и точности;
- контакты, авторство и версию приложения.

### 4.4. Технические требования

- Технологический стек на выбор: Streamlit или FastAPI.
- Модель должна загружаться один раз при запуске приложения, а не при каждом запросе.
- Ошибки ввода (некорректные или пустые значения) должны обрабатываться понятными сообщениями пользователю.

## Дополнительные критерии

- Развёртывание приложения в облаке (Streamlit Cloud, Render, Heroku и т. д.) с публичной ссылкой — **+5 баллов**.
- Использование продвинутых методов: стекинг моделей, автоматический подбор через Optuna, SHAP-анализ важности признаков — **+5 баллов**.
- Использование глобального репозитория — **+5 баллов**.

## Штрафные критерии

- Использование признака, позволяющего определить целевую переменную (утечка данных), — снижение баллов по пунктам 3 и 8.
- Отсутствие валидации по отложенной выборке или использование тестовой выборки при выборе гиперпараметров — снижение баллов по пункту 7.
- Неработающее приложение при сдаче — снижение баллов по пунктам 10–12.
